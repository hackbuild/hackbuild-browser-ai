# @hackbuild/stems

> Split a song into drums, bass, other and vocals with htdemucs, in the tab.

Generated by tools/llms.mjs from the TypeDoc JSON, the README and the examples of hackbuild-browser-ai. Human docs: https://hackbuild.github.io/hackbuild-browser-ai/docs/stems/

## Purpose

- Registers two htdemucs tiers with the models hub; onnxruntime-web runs them through `@hackbuild/devices`.
- Cuts a 44.1 kHz stereo mix into segments and joins the model output by its own overlap add with linear crossfades.
- Reports progress per segment and the realtime factor.
- Ships a stub separator for tests and pages without weights.

## Install

```sh
npm install @hackbuild/stems
```

It depends on `@hackbuild/models`, `@hackbuild/devices` and `@hackbuild/audio-dsp`. It has no peer dependencies: onnxruntime-web 1.27.0 loads at runtime through `loadOrt` in `@hackbuild/devices`, and you open the weight store with `@hackbuild/weights`.

## Examples

### quick start

```ts
import { loadOrt, ortProvider } from "@hackbuild/devices";
import { createHub } from "@hackbuild/models";
import { attachStems, separate } from "@hackbuild/stems";
import { openWeightStore } from "@hackbuild/weights";

// a hub with the htdemucs records (weights MIT); onnxruntime-web loads at runtime
const hub = createHub();
attachStems(hub);
const store = await openWeightStore();
hub.provide("ort", ortProvider({ runtime: loadOrt(), store }).factory);

// a 44.1 kHz stereo mix, for example from decodeAudio in @hackbuild/media
const left = new Float32Array(44100 * 10);
const right = new Float32Array(44100 * 10);

// separate on the fast tier, with progress per segment
const { stems, rtf } = await separate(hub, left, right, { model: "htdemucs-fast", onProgress: (p) => console.log(`segment ${p.done} of ${p.total}`) });
console.log(`vocals ${stems.vocals.left.length} samples, ${rtf.toFixed(2)}x realtime`);
```

## Mistakes to avoid

- Pass the runtime module in; never import it. WebLLM, wllama, transformers.js, onnxruntime-web, kokoro-js and MediaPipe are optional peers: load one with the package's loader or `importEsm` from @hackbuild/ai-env (pinned URLs, file:// safe) and hand the module to the package. A static `import` of a runtime breaks the single file build and pulls megabytes into every page.
- Fetch weights through @hackbuild/weights (`openWeightStore()`, then `store.get({ url, key, licence })`), or take a URL, ArrayBuffer or File from the user. Never bundle, commit or inline weights, and state the weight licence before the download starts.
- file:// rules: Chrome refuses module scripts, module workers and dynamic imports of file URLs on a page opened from disk. Use the single file build (`dist/single/index.iife.js`, a classic script that sets a `Hackbuild<Pkg>` global) or serve over http. There are no wasm threads, so no SharedArrayBuffer or cross origin isolation is needed; workers start classic from a Blob.
- Inject randomness as `Rng = () => number` where an option takes one; library code never calls `Math.random`.

## Errors this package throws

- `this htdemucs export needs a spectrogram input; use a waveform only export (StemSplitio htdemucs-onnx)` (the graph has two inputs): use the StemSplitio waveform only export
- `this model has no time domain output tensor` (no output of shape [1, tracks, 2, samples]): use the StemSplitio export
- `this model returns N stems, the pipeline expects 4` (the graph is not a four stem model): use a four stem htdemucs export
- `separation stopped` (AbortError) (the `signal` you passed aborted): expected; start again when you want stems
- `no factory for provider ort; call hub.provide("ort", ...)` (the hub has no ort factory): call `hub.provide("ort", ortProvider(...).factory)`
